# 마을 이동 서버 검토 및 보완

작성: 2026-10-04. 총괄 인계에 따라 서버 담당이 기존 절대 시각 예약 변경을 검토하고 입력 시점 정합성을 보완했다. 이 문서는 서버 담당의 추가 변경만 기록한다.

## 결과

상대 50ms 예약과 고정 0.05초 적분의 조합은 콜백 지연 및 틱 처리 시간을 이동 시간에서 누락한다. 총괄의 `expires_at(nextTickTime)` 예약, 지난 예약 건너뛰기, 실제 경과 시간 계산 방향은 타당하다. 절대 예약과 0.25초 적분 상한은 유지했다.

다만 공통 `lastTickTime`만 사용하면 틱 사이에 수락한 최신 방향이 이전 시간 전체에 적용된다. 예를 들어 지난 계산 이후 90ms 동안 오른쪽 입력이 유지되다가 왼쪽 입력을 받고 10ms 뒤 계산하면 기존 변경은 100ms 전체를 왼쪽으로 계산한다. 보완한 경로는 입력 수락 직전 기존 방향으로 90ms를 계산하고 다음 틱에서 새 방향으로 10ms를 계산한다. 이는 코드의 시간 구간을 검토한 예시이며 실행 테스트 결과가 아니다.

* 대각선 정규화, 맵 walkSpeed, 기존 ConstrainMovement의 4단위 경로 검사, 구역 관리, 전환 구역 재진입 방지, 던전 플레이어 틱 제외를 유지했다.

## 클라이언트 연계 사항 및 남은 한계

* Town 기본 예약 주기는 50ms(20Hz), 이동 스냅샷은 실행된 두 틱마다 전송(정상 부하에서 약 10Hz). serverTick은 콜백 횟수이며 지난 예약 건너뛰기가 있으므로 serverTick 차이 × 50ms를 정밀한 실제 시간으로 해석하면 안 된다.
* lastProcessedInput은 수락한 입력의 sequence다. 스냅샷은 그 뒤의 틱 시각 위치와 최종 속도를 담는다. 입력 처리에서 이동을 계산해도 추가 스냅샷을 즉시 보내지는 않는다.
* 첫 입력 응답까지의 시간에는 TCP 전달, Town strand 대기, 틱 및 스냅샷 대기가 포함된다. 순수 RTT나 단방향 지연으로 간주할 수 없다. 기존 패킷에는 서버 계산 시각/수락 시각 필드가 없으므로 클라이언트는 제한적인 추정과 보정을 사용해야 한다.
* 클라이언트 외삽은 응답의 velocity와 충돌 제한을 사용하고, 정지 응답에서는 외삽하지 않아야 한다. 오래된 sequence/tick 응답 제외 및 맵 전환·던전 전환 시 추정 초기화를 클라이언트 담당이 확인해야 한다.
* 0.25초를 넘는 서버 정체의 이동 시간은 의도적으로 버린다. 이 경우 클라이언트 보정이 남는다. 입력 수락 시각 이전의 네트워크/strand 지연을 재현하거나 역산하는 기능은 없다.
* 입력마다 충돌 계산이 추가되어 처리 비용이 늘어난다. 오래된 입력은 계산 전에 제외하지만 정상 입력 빈도에 따른 부하는 실행 검증하지 않았다.
* 방향 전환, 입력 묶음 수신, 정지/입력 만료, 벽 접촉, 맵 전환, 던전 복귀, 실제 지연과 서버 부하에서의 결과는 정적 검토만으로 확정할 수 없다. 실행 승인이 있을 때 확인할 항목이다.
