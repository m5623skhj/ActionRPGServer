# 스킬 트리와 단축키 구현 요구사항

상태: 성장 정책과 UI 치수 확정, 서버·클라이언트 소스 및 아이콘 통합과 정적 검토 완료. 빌드·테스트·게임 실행은 하지 않았다.

## 사용자 확정 사항

* 메뉴의 스킬 항목을 누르면 현재 선택한 캐릭터의 스킬 트리를 연다.
* 트리에는 해당 캐릭터의 모든 스킬을 표시한다. 요구 레벨 미달 또는 미습득 스킬을 숨기지 않는다.
* 스킬 선택 시 이름, 간략한 설명, 쿨타임, 공격력 또는 버프 효과, 사용 가능한 지상/공중 상태를 표시한다.
* 요구 레벨, SP 비용, 선행 스킬과 조건을 만족하지 못하는 이유도 표시한다.
* 레벨업 시 데이터에 정의된 SP를 지급한다. SP를 소비해 스킬을 습득한다.
* 캐릭터 일치, 요구 레벨, 선행 조건, 보유 SP를 모두 만족해야 습득할 수 있다.
* 미습득 스킬은 커맨드와 단축키 모두 사용할 수 없고 단축키에 드래그 등록할 수도 없다.
* 습득한 스킬 아이콘을 A, S, D, F, G, H 슬롯으로 드래그해 등록한다.
* 한 스킬은 한 슬롯에 등록한다. 기존 슬롯에 드롭하면 교체하고, 슬롯 오른쪽 클릭은 해제한다. 창 밖 드롭은 취소한다.
* 캐릭터별 단축키 설정은 클라이언트 설정 파일에 저장하고 재실행 시 복원한다. 복원 시 미습득/다른 캐릭터/삭제된 스킬 등록을 검증한다.
* 단축키는 최초 누름에 한 번 발동한다. 길게 누르는 자동 반복은 없다.
* 스킬 창을 포함한 메뉴 편집 중 단축키 사용을 차단한다. 채팅/텍스트 입력이 있는 경우 입력과 충돌하지 않게 한다.
* 사용할 수 없는 입력은 예약하지 않는다. 쿨타임이 끝난 뒤 이전 입력으로 자동 발동하지 않는다.
* 커맨드와 단축키는 같은 스킬 실행 경로와 쿨타임을 공유한다.
* 쿨타임 중 아이콘을 회색으로 표시하고 남은 시간을 겹쳐 표시한다. 종료 시 원래 색으로 복원한다.
* 남은 시간이 60초 미만이면 x.x초, 60초 이상이면 분 단위로 표시한다. 구체적 반올림은 UI 계약에 명시한다.

## 기술적 확인 사항

* 현재 TownServer와 GameRoomServer의 플레이어 상태에는 레벨, 경험치, SP, 습득 스킬이 없다.
* 현재 스킬 목록에는 Character1.FrontKick 한 개가 등록되어 있다. 트리를 풍성하게 보이게 하려고 가짜 실행 스킬을 추가하지 않는다.
* PlayerSkills.json은 이름, 캐릭터, 커맨드, 쿨타임, 실행 값과 모션을 정의한다. 현재 엄격한 v1 파서는 추가 필드를 거절한다.
* 서버/클라이언트 카탈로그 일치 검사가 있으므로 한쪽 파일만 변경해서는 안 된다. 스킬 편집기의 출력 계약과도 충돌하지 않아야 한다.
* 현재 선택 키는 방향키와 Z/C/X/V이며 A/S/D/F/G/H는 스킬 슬롯에 사용할 수 있다.
* 현재 입력에는 마우스 누름만 있으므로 드래그 종료, 오른쪽 클릭, 창 포커스 해제 시 드래그 취소 처리도 필요하다.
* 스킬 사용은 GameRoom strand에서 검증한다. 습득 검증과 SP 차감도 소유 strand에서 한 번에 처리해야 한다.

## 구현 완료 기준

1. 서버가 레벨/SP/습득 정보를 소유하며 클라이언트가 임의의 레벨/SP/습득 목록을 선언해 사용 권한을 얻을 수 없다.
2. 습득 요청을 반복하거나 동시에 보내도 SP가 중복 차감되거나 스킬이 중복 습득되지 않는다.
3. 선행 조건은 같은 캐릭터의 실제 스킬 ID를 참조한다. 자기 참조, 누락 참조, 선행 조건 순환은 데이터 로드 단계에서 거절한다.
4. 스킬 트리에서 잠김/습득 가능/습득 완료 상태와 연결선을 구분하고 남은 SP를 표시한다.
5. 미습득 스킬을 커맨드, 단축키, 직접 패킷으로 사용하려 해도 서버에서 거절한다.
6. 서버에서 사용을 승인한 스킬만 권한 있는 쿨타임을 시작한다. 서버 거절을 성공처럼 표시하지 않는다.
7. 캐릭터 변경과 마을/던전 전환 후 습득 목록과 단축키가 올바른 캐릭터 상태를 사용한다.
8. 소스 데이터와 실행 위치 데이터를 구분해 적용 범위를 보고한다. 런타임에서 확인하지 않았다면 정적 검사만 했다고 명시한다.

## 담당 범위

* 총괄: 성장 정책 확인, 데이터/서버/클라이언트 계약 정리, 최종 연결과 검증.
* 클라이언트 담당: 우선 화면 배치와 슬롯/아이콘/키 라벨/쿨타임 영역 치수 결정. 프로토콜과 공용 데이터 변경은 계약 확정 후 진행.
* 그래픽 담당: 크기 계약 확정 후 스킬 아이콘 제작. 현재는 참조 자산과 픽셀 스타일/작은 크기 가독성 검토.
* 이 요청은 기존 모션의 재생성 또는 기존 미커밋 작업 정리를 승인하는 것이 아니다.

## 확정된 성장 정책

* 초기 캐릭터 레벨 1, 초기 SP 0, 레벨업당 200 SP를 데이터로 관리한다.
* 앞차기 1단계는 요구 캐릭터 레벨 1, 소모 SP 20이다.
* 모든 스킬은 최초 요구 레벨에서 스킬 단계마다 캐릭터 요구 레벨이 2씩 증가한다. 매 단계 비용은 최초 SP 비용과 동일하다.
* 앞차기 공격력은 25 + 5 × (습득 스킬 레벨 - 1)이다. 1단계 25, 2단계 30, 이후 5씩 증가한다.
* 최대 스킬 레벨은 선택적으로 지정한다. 앞차기는 지정하지 않아 기획상 상한 없이 시작한다.
* 이번 구현은 레벨/SP 관리부터 진행한다. 경험치 획득 및 자동 레벨업 조건은 추가하지 않는다.
* 클라이언트가 서버 레벨을 올리는 요청 패킷은 추가하지 않는다.
* 사용자 결정에 따라 레벨/SP/습득 정보는 접속 중인 캐릭터의 서버 메모리에서만 관리한다. 마을/던전 전환 중에는 유지되며 접속 종료 시 사라진다. 영구 저장과 고정 프로필 이름은 이번 범위에서 제외한다.

## 확정된 UI 계약

* 기준 화면 1280×720, 단축키 바 440×96, 슬롯 64×80, 아이콘 56×56, 상세 아이콘 96×96.
* 작은 창에서는 아이콘 48×48, 바 382×88을 사용한다. 최소 클라이언트 크기는 640×360이며 좁은 창에서는 트리와 상세 내용을 탭으로 전환한다.
* 쿨타임은 60초 미만에서 소수 첫째 자리까지 올림하여 x.x초로, 60초 이상에서 분을 내림하여 최소 1m으로 표시한다.
* 색상 아이콘에서 런타임 회색 효과를 적용한다. 회색 PNG를 따로 저장하지 않는다.
* 권장 원본은 128×128 RGBA와 8px 여백이다. 실제 제작 PNG는 1254×1254이며 UI 표시 크기로 선형 축소한다. 동일 여백과 저알파 잔여 기준의 미충족 사항은 GRAPHICS_REPORT.md에 기록했다.
* 슬롯 설정만 캐릭터별 로컬 파일에 저장하며 레벨/SP/습득 정보를 로컬 파일에 저장하지 않는다. 두 클라이언트가 같은 캐릭터 슬롯 파일을 사용하는 경우 마지막 저장이 반영된다.

백업 파일은 생성하지 않는다. 수정 완료 시 '*' 형식 커밋 로그를 출력하고, 실제 Git 커밋/푸시 여부는 별도로 보고한다.
