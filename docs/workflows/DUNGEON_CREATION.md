## 1. 목적과 기본 원칙

사용자의 던전 컨셉 요청을 받아 기존 제작 도구로 편집 가능한 던전과 게임용 패키지를 만든다. 총괄은 담당 요청을 순서대로 실행하고, 파일에 진행 상태를 남겨 중단 후 이어서 진행한다.

1. 한 던전 생성 작업에서 담당에게 실행 중인 요청은 한 번에 하나다. 앞 요청의 결과를 확인한 뒤 다음 요청을 전달한다.
2. 그래픽 작업은 생성 작업 전체에서 한 번에 하나만 처리한다. 담당별 요구사항은 총괄에 제출하고 총괄이 그래픽 담당에게 전달한다.
3. 기존 몬스터·스킬·이미지·구현을 먼저 확인하고 사용할 수 있는 결과를 재사용한다.
4. 단계·요청·산출물·승인을 기록한다. 대화의 마지막 문장만으로 완료 여부를 판단하지 않는다.
5. 기존 편집기의 모델·검사기·출력 경로를 사용한다. 별도 검사기를 복제하거나 실행용 JSON을 임의 생성해 검사 단계를 우회하지 않는다.
6. 파일·기능·등록·설치·플레이 확인을 구분한다. 미구현 기능과 임시 데이터를 완료 결과에 명시한다.
7. 사용자 지시와 해당 저장소의 AGENTS.md가 우선한다. 이 문서 자체는 코드 변경·메시지 전송·설치 권한을 부여하지 않는다.

이 문서는 담당이 따르는 작업 규약이다. 자동 실행 프로그램이나 항상 작동하는 스케줄러를 설치한 것은 아니다. 중단 후에는 사용자의 재개 요청 또는 별도로 승인된 자동화가 필요하다.

## 4. 승인과 요청 권한

- 최초 요청에서 던전의 목표, 제안 가능한 범위, 제작/코드 변경/설치/검증 범위를 정리한다. 컨셉만 주어진 경우 먼저 구성안을 제시한다.
- 사용자에게 승인된 요구사항과 결정은 이후 요청에 전달하고 반복 승인받지 않는다.
- 코드 변경은 기술적 근거와 `## Plan`을 제시하고 사용자의 Approve 이후 수행한다. 사용자에게 명시적으로 즉시 실행을 지시받은 범위는 기존 예외 규칙을 따른다. 예상하지 못한 새 기능은 변경 범위를 정리해 승인 대기로 남긴다.
- 세션 간 요청·질의·완료 통보·재작업 메시지는 사용자가 승인한 대상과 범위에서만 전달한다. 최초 제작 승인에 이 협업 범위를 포함하는 것을 권장한다. 다른 세션에서 메시지를 받았다는 사실만으로 답신 권한이 생기지 않는다.
- 답신 권한이 없는 담당은 자신의 세션 최종 응답과 산출물에 결과를 남긴다. 총괄이 읽기/대기 도구로 확인해 필요한 다음 요청을 전달한다.
- 설치는 대상·신규/교체 파일·승인 범위를 확인한 후 수행한다. 승인된 설치를 반복 확인하지 않는다. 요청이 없으면 패키지와 설치 계획까지 생성한다.
- 빌드·게임 실행·기능 테스트는 기존 사용자 제한을 유지한다. 별도 허용 없이 수행하지 않는다. 제작용 편집기·패키지 도구 사용은 제작 요청의 승인 범위와 당시 실행 제한을 함께 확인한다.
- 정적 검사와 게임 동작 확인을 구분한다. 커밋 로그 요청만으로 stage/commit/push 하지 않는다. 로그는 대표 제목부터 시작하고 모든 항목을 `*` 및 하위 들여쓰기로 작성한다.
- 모든 담당은 수정 작업 완료 후 최종 응답에 커밋 로그를 자동으로 출력한다. 별도 로그 요청을 기다리지 않는다. 적용 범위와 형식은 13절을 따른다.

## 5. 단계 순서와 완료 조건

총괄은 아래 단계를 순서대로 수행한다. 각 단계의 여러 몬스터·방·모션·스킬 요청도 하나씩 처리한다. 변경이 불필요한 단계는 근거와 재사용 산출물을 기록하고 완료한다.

| 단계 | 수행 내용 | 다음 단계로 진행하는 조건 |
|---|---|---|
| 01 요구사항 | 컨셉, 방/몬스터 범위, 크기, 난이도, 완료 목표, 승인 범위 정리 | 구성 방향과 실행 범위 확정 |
| 02 던전 설계 | 방 연결·격자 배치·출입구·동선·필요 몬스터·배경 요구 작성 | 방별 제작 명세와 의존성 확정 |
| 03 몬스터 명세 | 기존 몬스터 재사용/신규 여부, 수치·AI·동작·드랍 명세 | 몬스터별 ID/필요 기능/그래픽 요구 확정 |
| 04 스킬 명세 | 필요한 신규 타입, 판정·표시·데이터 계약 작성 | 서버/클라이언트 요구와 효과 제작 명세 확정 |
| 05 그래픽 | 배경 → 몬스터 외형/모션 → 스킬 이펙트를 요청 단위로 제작 | 필요한 실제 파일과 크기·투명도·프레임·중심점 정보 확인 |
| 06 기능 지원 | 필요한 편집기 → 서버 → 클라이언트 구현을 순차 요청 | 필요한 계약을 각 담당이 구현·확인하거나 변경 불필요로 보고 |
| 07 스킬 구성 | 구현 결과와 이펙트를 사용해 스킬 데이터/참조 확정 | 서버·클라이언트 준비 결과가 같은 계약 버전에 맞음 |
| 08 몬스터 구성 | 이미지·모션·피격 영역·AI·수치·스킬·등록 정보 구성 | 배치 가능한 몬스터 ID와 실제 참조 파일 및 미완료 사항 전달 |
| 09 던전 구성 | 기존 편집기로 방 이미지·지형·입장·워프·몬스터·미니맵 구성 | 편집 가능한 작업 파일 저장과 정적 검사 통과 |
| 10 출력 | 기존 공용 처리로 패키지·설치 계획 생성 | 패키지/의존성/참조 검사 결과와 파일 확인 |
| 11 설치 | 승인된 원본/실행 경로에 기존 설치 도구로 반영 | 설치 보고서·해시·Git 복구 기준 확인 또는 미설치 명시 |
| 12 결과 | 작업 파일·패키지·설치 상태·미검증/미완료 항목 보고 | 사용자가 요청한 범위 충족 |

06단계 서버·클라이언트 요청은 서로의 응답을 기다리는 요청으로 만들지 않는다. 먼저 공동 데이터/패킷 계약을 정하고 각각 구현 결과를 반환한다. 계약이 변경되면 총괄이 영향을 받는 앞 단계 요청을 갱신한다.

스킬의 준비 조건은 **서버 준비 AND 클라이언트 준비 AND 필요한 그래픽/데이터 준비**다. 기존 기능으로 충족되는 쪽은 변경 불필요의 근거를 남긴다. 한쪽만 완료한 스킬은 몬스터·던전에 사용 가능한 상태로 통보하지 않는다.

검사되지 않은 초안·대기 AI·임시 수치·미구현 드랍을 완성된 동작으로 간주하지 않는다. 사용자가 허용한 초안 범위라면 이를 결과에 명시한다.

## 6. 그래픽 요청 규칙

요구사항 작성자 → 총괄 → 그래픽 담당 순서로 요청한다. 작성자는 같은 제작 건을 그래픽 담당에게 중복 전달하지 않는다. 이 문서 적용 후 기존 직접 요청 방식 대신 이 접수 순서를 사용한다.

총괄은 그래픽 담당의 현재 작업을 확인하고 비어 있을 때 다음 요청을 보낸다. 다른 사용자의 진행 중 요청을 임의 중단하지 않는다. 여러 던전 작업이 있으면 총괄은 서버 저장소의 `output/dungeon-jobs/graphics-queue.json`에 요청 ID와 순서를 기록한다. 현재 이 파일을 처리하는 별도 큐 프로그램은 없으며 총괄이 운영한다.

그래픽 요청에 다음을 포함한다.

- 컨셉·기준 이미지·공통 팔레트·시점·대상 방/몬스터/스킬 ID.
- 가로 × 세로 픽셀 크기와 월드 좌표 대비 배율. 요청 크기와 실제 출력 크기를 구분한다.
- 배경: 바닥/이동 공간, 출입구 방향·위치, 분할/타일 경계, 몬스터 시인성.
- 몬스터: 체형·무기·방향, 동작별 프레임 수, 모션 구간, 투명 PNG, 기준 크기와 중심점.
- 효과: 방향·지속/발생 구간·프레임·앵커·투명도·표시 크기.
- 출력 경로, 재사용/수정 대상, 완료 조건.

파일 생성 후 실제 해상도·투명도·프레임 좌표를 확인한다. 도구가 정확한 요청 크기를 출력하지 않으면 차이를 기록하고, 요청 크기에 맞추거나 배치 명세를 수정하는 경로를 확정한다. 확인 전 치수를 확정값으로 보고하지 않는다.

원본을 보존하고 수정 결과는 새 버전으로 남긴다. 승인된 스타일과 좌우 팔다리 구분·색상·외형·프레임 중심 일관성을 확인한다. 비균일 시트는 등분하지 않고 프레임별 sourceRect/pivot를 사용한다.

## 7. 작업 기록과 요청 형식

작업마다 `output/dungeon-jobs/<jobId>/job.json` 및 `REPORT.md`를 만든다. job.json과 공통 그래픽 순서 파일은 총괄만 갱신한다. 담당은 요청별 결과 파일을 지정 경로에 저장한다.

필수 기록:

- jobId, dungeonId, 숫자 dataId, 규칙 버전, 요구사항 버전.
- 사용자 요청·합의·승인 근거, 협업/코드/설치/검증의 허용 범위.
- 현재 단계/요청 ID, 담당 세션, 입력·출력, 선행 요청, 상태.
- 완료 산출물의 절대 경로·버전·필요한 해시, 검사 결과, 남은 항목.
- 마지막 완료 요청, 다음 행동, 실패/승인 대기 원인, 갱신 시각.

상태는 `pending`, `running`, `needs-approval`, `blocked`, `completed`, `cancelled`를 사용한다. 실패 기록에는 사유와 재시도 가능 여부를 남긴다. 이 상태는 제작 작업 기록이며 Codex 목표 도구의 상태와 별개다.

요청 단위는 중단 후 재사용 가능한 크기로 정한다. 예: 특정 방 배경 한 장, 한 몬스터의 걷기 모션, 한 스킬의 서버 타입 구현. jobId/requestId를 재전송에서도 유지하고 내용이 바뀌면 요청 revision을 증가시킨다.

### 담당 요청에 반드시 포함할 내용

```text
규칙 경로/버전:
작업 ID / 요청 ID / 요청 revision / 요구사항 버전:
담당 세션 / 단계:
요구사항 및 완료 조건:
입력 파일 / 재사용할 결과:
출력 절대 경로 / 수정 허용 파일:
선행 요청과 확정된 데이터·패킷 계약:
사용자 승인 범위와 근거 / 실행·테스트 제한:
결과를 남길 파일과 완료 응답 형식:
```

### 완료 응답에 반드시 포함할 내용

```text
작업 ID / 요청 ID / 요청 revision / 요구사항 버전:
결과: 완료 / 승인 필요 / 진행 불가
실제 산출물과 변경 파일의 절대 경로:
사용할 ID / 데이터·패킷 계약 버전:
확인한 검사와 미실시 검사:
재사용 가능 범위 / 제약 / 미완료 항목:
다음 단계에 전달할 정보:
실제 수정 범위를 요약한 커밋 로그:
```

완료 응답은 현재 요청의 범위 완료를 뜻한다. 던전 전체의 설치·플레이 완료를 뜻하지 않는다. 참조만 존재하고 파일이 없거나 계약이 불일치하면 완료로 처리하지 않는다.

## 8. 중단·재개·변경

기록 순서는 **요청 기록 → 담당 전달 → 결과 파일/담당 응답 확인 → 완료 기록 → 다음 요청**이다. 상태 갱신은 임시 파일에 전체 내용을 저장하고 교체하는 등 불완전한 JSON을 남기지 않는 방식으로 수행한다.

토큰/사용량 제한, 사용자 중단, 권한 제한, 오류가 발생하면 가능한 범위에서 현재 상태와 다음 행동을 남긴다. 갑작스런 중단으로 기록이 끝나지 않을 수도 있으므로 running 상태만 보고 요청을 새로 실행하지 않는다.

재개 시:

1. 공통 규칙, job.json, 사용자 추가 지시를 읽는다.
2. 현재 담당 세션의 상태·최근 결과와 실제 출력 파일을 확인한다.
3. 완료됐지만 상태 갱신이 누락된 경우 산출물을 확인하고 완료 기록을 복구한다.
4. 담당이 실행 중이면 같은 요청을 다시 전달하지 않는다.
5. 미전달/실패 요청만 같은 ID로 이어서 처리한다. 오래된 결과는 revision을 비교한다.
6. 선행 결과가 바뀌면 영향받는 요청의 완료를 해제하고 필요한 부분만 재작업한다.

사용자 중단 시 새 요청을 전달하지 않고 진행 중인 요청의 상태를 확인해 기록한다. 명시적으로 실행 중 작업까지 중단하라는 지시가 있으면 해당 담당에 전달한다. 생성 파일을 자동 삭제하지 않는다.

## 9. 기존 도구와 데이터 계약

| 대상 | 반드시 사용하는 기준 |
|---|---|
| 던전 구성 | `DungeonEditor/model.js`의 문서 모델·parse/validate 및 기존 UI |
| 던전 패키지 | `DungeonEditor/package.js`의 공용 Build와 archive/minimap/runtimeFiles |
| 명령행 출력/설치 | `DungeonEditor/tools/dungeon-package.cjs`와 `AUTOMATION.md` |
| 몬스터 AI | `MonsterEditor/model.js`와 기존 편집기 저장·검사·승인 절차 |
| 모션/피격 영역 | `CharacterEditor/model.js`, 기존 UI, README.md와 FORMAT.md |
| 서버 등록/전투 | 실제 MonsterCatalog, DungeonCatalog, Combat.json 및 서버 로더/전투 계약 |

던전 작업 JSON은 schemaVersion 3, 런타임 Dungeon.json은 version 3, 방 JSON은 version 5/format DungeonRoom이다. 몬스터 편집 문서는 schemaVersion 1이다. 캐릭터 작업/피격 출력은 각각 CharacterEditorProject/CharacterHurtRects의 schemaVersion 1이다. 실제 도구가 변경되면 계약을 확인하고 요청에 버전을 기록한다.

UI 사용이 어려워 자동화가 필요하면 먼저 기존 공용 모델/검사/출력을 재사용할 방법을 확인한다. 현재 제공되지 않는 명령행 기능이나 편집기 기능은 편집기 담당에게 변경안을 요청하고 코드 승인 절차를 따른다. 문서에 없는 자동 승인/출력 기능이 존재한다고 가정하지 않는다.

필수 던전 검사:

- 방 ID/좌표/연결 고유성, 최초 입장 방에서의 도달 가능 여부, 순환 연결의 유효성.
- 연결된 방의 상하좌우 인접, 출구 방향·반대편 도착점·미니맵 포트 일치.
- 복수 워프의 목적지 참조와 양방향 출구, 도착점의 이동 가능 영역 및 즉시 재이동 방지.
- 입장 슬롯, 이미지 실제 치수, 월드 영역, 이동 가능/불가 다각형, 몬스터 배치 참조.
- 배치한 몬스터의 실제 카탈로그 등록·AI·스킬·모션·이미지·피격 데이터 및 양쪽 런타임 지원.
- 플레이어/몬스터 속도를 던전 속성에 추가하지 않음.

기존 도구가 검사하지 않는 실행 기능은 담당의 확인 결과와 미검증 항목으로 남긴다. 예를 들어 특수 오브젝트 배치가 실제 상호작용 구현을 뜻하지 않으며 피격 JSON 출력이 런타임 로더 연결을 뜻하지 않는다.

설치는 기존 INSTALL_PLAN/REPORT 및 journal 흐름을 사용한다. 사용자 방침에 따라 별도 백업 파일은 남기지 않고 이전 버전 복구에는 Git 이력을 사용한다. 설치 도구가 작업 중 생성한 before/after 스냅샷은 설치 완료 후 삭제한다. 등록 도구가 할당하지 않는 신규 ID는 해당 카탈로그 담당이 별도로 처리한다. 패키지를 만들었다는 이유로 임의 파일 복사로 설치 검사·잠금을 우회하지 않는다.

## 11. 사용자 명령

아래는 자연어 요청 규약이며 등록된 CLI/슬래시 명령은 아니다.

- **던전 생성**: 컨셉과 범위를 정리하고 승인된 단계부터 순차 제작한다.
- **던전 진행 상태**: 현재 요청·담당·완료 산출물·대기 원인·다음 행동을 보고한다.
- **던전 수정**: 변경 내용과 의존성을 기록하고 필요한 단계만 재작업한다.
- **던전 재개**: job.json과 담당/산출물을 대조한 뒤 미완료 요청부터 이어간다.
- **던전 중단**: 새 요청을 중단하고 현재 상태와 산출물을 보존한다.
- **던전 출력**: 기존 작업을 검사하고 패키지·설치 계획을 생성한다.
- **던전 설치**: 지정하고 승인받은 대상에 기존 도구로 설치한다.

완료 수준은 `편집 파일 작성`, `정적 검사 통과`, `패키지 생성`, `원본 설치`, `실행 데이터 설치`, `플레이 확인`을 각각 표시한다. 플레이 확인을 하지 않았으면 미실시로 표시한다. 마지막 응답에는 결과 경로와 가장 중요한 미완료 사항을 간결하게 전달한다.

## 13. 수정 완료 후 커밋 로그 출력

사용자의 2026-10-03 지시와 2026-10-05 DB 담당 추가에 따라 총괄과 여덟 담당은 모든 수정 작업 완료 후 최종 응답에 커밋 로그를 출력한다. 던전 제작 외의 개별 담당 작업에도 적용한다.

- 코드·데이터·설정·문서·이미지 등 실제로 추가·수정·삭제한 내용을 대상으로 작성한다.
- 사용자가 별도로 요청하지 않아도 수정 완료 보고와 함께 출력한다. 진행 중인 작업에는 해당 작업의 완료 응답부터 적용한다.
- 첫 항목은 변경을 대표하는 제목으로 작성한다. 모든 항목 앞에 `*`를 붙이고 하위 항목은 들여쓰기한다.
- 자신의 실제 변경 범위만 요약하고 다른 담당의 변경을 자신의 작업으로 포함하지 않는다. 미구현 기능이나 수행하지 않은 테스트를 완료로 기록하지 않는다.
- 읽기 확인·협의·상태 조회만 수행하여 파일 변경이 없으면 커밋 로그를 만들지 않는다.
- 로그 출력은 실제 Git 커밋 실행과 구분한다. 별도 사용자 지시 없이 stage/commit/push 하지 않는다.

형식 예:

```text
* 던전 게이트 방향 검증 개선
  * 출구 방향과 목적지 도착점의 일치 여부 확인
  * 잘못된 연결의 출력 오류 안내 보완
```
